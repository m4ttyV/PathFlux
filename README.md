# PathFlux

Windows 10/11 x64 desktop-клиент выборочного проксирования на C# / .NET 10 / Avalonia. Реализованы формы профилей и правил, процессы, DPAPI, атомарный JSON, TCP-диагностика, проверка UDP echo через SOCKS5 relay, компилятор sing-box и отдельный агент с UAC.

**Начните с [пошаговой инструкции](docs/user-guide.md)** — она также открывается кнопкой «Как пользоваться» сверху окна. В настройках есть установка комплектного движка: путь и SHA-256 сохраняются автоматически. Новый SOCKS5-профиль получает TCP/IPv4 и автоматический режим UDP; существующие профили сохраняют свои настройки.

[Изменения удобства настройки и результаты проверки](docs/qol-2026-10-25.md): автоматические порты Docker и кнопка проверки реальной передачи UDP без собственного echo-сервера.

Выборочный TCP подтверждён на Windows 11 через настоящий TUN и UAC-агент, включая Docker SOCKS5/OpenVPN. UDP SOCKS5 включается вручную; совместимость конкретного сервера и приложения требует проверки. Пользователь подтвердил шестичасовой сеанс Discord, но это не приёмка всех окружений. Один успешный check или HTTPS-ответ не подтверждает выбранный маршрут. Точный PID и потомки остаются Experimental и доступны только для TCP; системный kill switch недоступен. Полная [матрица возможностей](docs/limitations.md).

Строгий UDP-транспорт интегрирован в production-агент: отклонение SOCKS-фрагментов, восстановление ассоциаций и явный Docker NAT с динамическим портом релея. По умолчанию UDP выключен, миграция старых настроек его не включает. [Включение, архитектура и результаты этапа 3](docs/udp-production-stage3.md), [сценарий Discord на 30/60 минут](docs/discord-acceptance.md), [ограничения DNS/WFP](docs/dns-wfp-stage3.md).

Включение или отключение стороннего VPN не требует возвращать всю сеть к старому состоянию для остановки PathFlux. Собственные ресурсы проверяются отдельно; при изменении общей сети исходный снимок сохраняется как неподтверждённый архив. [Остановка и переходы VPN](docs/vpn-transition-recovery.md).

![Интерфейс PathFlux](docs/images/overview.png)

Крестик окна скрывает PathFlux в системный трей; движок продолжает работу. Нажатие на значок или пункт «Открыть PathFlux» возвращает окно. Для завершения выберите «Выход» в меню трея: приложение сначала остановит движок и проверит очистку собственных сетевых ресурсов. Если остановка не подтверждена, окно откроется с сообщением и возможностью повторить её.

Для SOCKS5 без IPv6 доступен режим TCP/IPv4 по имени TLS с DoH через тот же прокси: [техническое описание](docs/discord-connectivity-2026-10-24.md). Для новых профилей он включён по умолчанию, явные настройки старых профилей сохраняются. Это не глобальное отключение IPv6 и не замена системного DNS.

25 октября пользователь подтвердил около шести часов штатной работы голоса и демонстрации Discord. Проверка Chrome описана отдельно: [маршрутизация браузера и совпадение внешнего IP](docs/browser-routing-2026-10-25.md).

Для точного дерева PID добавлен отдельный экспериментальный TCP-backend с проверкой новых детей и внуков: [описание, ограничения и сборка](docs/process-tree-backend.md). Он выключен по умолчанию; UDP-правила дерева не допускаются до приёмки.

## Сборка и запуск

Требуется Windows x64 и .NET SDK 10.0.401 (закреплён в global.json).

```powershell
dotnet restore PathFlux.slnx
dotnet build PathFlux.slnx -c Release
dotnet test PathFlux.slnx -c Release --no-build
dotnet run --project PathFlux/PathFlux.csproj -c Release --no-build
```

UI запускается с обычными правами. Сборка автоматически кладёт агент в `agent/` рядом с приложением. Только кнопка запуска движка вызывает UAC для отдельного агента. Для portable-папки: `./scripts/publish.ps1`; требуется .NET Runtime 10 x64.

## Первая настройка

1. Получить полную portable-папку, открыть «Настройки» → «Установить движок PathFlux». Проверенный пакет содержит модифицированный sing-box 1.14.3, исходники и лицензию; установка не требует интернета или UAC. Путь и SHA-256 заполняются и сохраняются автоматически. Бинарник не хранится в Git, но включается в опубликованную папку engine-package.
2. Если нужен свой официальный sing-box, использовать `./scripts/get-engine.ps1 -Version 1.14.3` и указать полученные путь и SHA-256 вручную. Официальный движок не поддерживает дерево PID. Приложение и агент проверяют хеш, версию ≥ 1.12.2, платформу Windows x64 и результат `sing-box check`. [Совместимость версий](docs/engine-compatibility.md).
3. В «Прокси» добавить свой SOCKS5 или HTTP/HTTPS CONNECT. `127.0.0.1:1080` — только пример; приложение не устанавливает и не перенастраивает OpenVPN/Docker.
4. В «Диагностика» проверить TCP CONNECT к выбранной цели. UDP ASSOCIATE проверяет только согласование. Для проверки передачи пакетов запустить [подконтрольный UDP echo-сервер](docs/udp-diagnostics.md), указать его IP/порт и нажать «Проверить UDP echo». Сохраняются число пакетов, задержка и время проверки; положительный результат актуален 15 минут и относится только к relay. Изменение адреса/авторизации профиля требует нового теста.
5. В «Процессы» выбрать процессы и создать постоянное TCP-правило по имени/пути. Либо создать правило вручную. Меньший приоритет применяется первым, UUID разрешает равенства.
6. Проверить конфигурацию и запустить агент. TUN затрагивает системные маршруты; сначала ознакомиться с [сетевой проверкой и recovery](docs/network-design.md). Статус Degraded сохраняется из-за ограничений UDP/PID/DNS и неполной матрицы сетевой приёмки.

Профили и правила хранятся в `%LOCALAPPDATA%/PathFlux/config.json`; пароли — в отдельном DPAPI-хранилище этого пользователя. Изменение настроек во время работы запрещено: остановить → сохранить → запустить. Необработанная конфигурация движка и его stderr с возможными секретами на диск не пишутся.
