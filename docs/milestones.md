# Вехи и критерии завершения

Первая итерация объединила тестируемую часть этапов 0–1. Вторая добавляет проверку UDP relay и сохранение её результатов. Сетевая приёмка Windows остаётся открытой; этап 1 нельзя считать полностью принятым только по сборке и unit-тестам.

## 0. Каркас и исследование — Partial

- Сохранён существующий Avalonia UI, добавлены Domain / Application / Infrastructure / Engine / Agent.
- Настройки, доменные профили и правила отделены от JSON внешнего движка.
- Выбран адаптер sing-box с фиксированной версией и проверкой бинарника; WinDivert отсутствует.
- Зафиксированы ограничения TUN, DNS, UDP, PID и системного kill switch.
- Открыто: подтвердить TUN на Windows 10 и 11, process_name/process_path, приоритеты, отсутствие петель и системные последствия.

## 1. Рабочий клиент и selective TCP — Partial

- Реализованы формы профилей SOCKS5 / HTTP / HTTPS CONNECT, постоянные правила, список процессов, сохранение и DPAPI.
- Реализованы валидация, сортировка по приоритету и UUID, генерация JSON, вызов `sing-box check`, запуск агента и остановка.
- Реализована TCP-диагностика прокси; совпавший Proxy UDP отклоняется.
- Компилятор отклоняет точный PID, дочерние процессы, временное lifetime и неподдерживаемый Direct fallback.
- Открыто: ручная приёмка по `network-design.md`, включая внешние SOCKS5 / HTTP / HTTPS upstream, два профиля, два одинаковых имени EXE, остальные приложения Direct, отказ upstream, отсутствие секретов в артефактах и восстановление сети.

Приёмка этой вехи требует доказательств реального selective TCP. Локальный TCP CONNECT тест и успешный `sing-box check` недостаточны.

## 2. UDP, DNS, восстановление — Partial

- Реализована отдельная UDP echo-диагностика SOCKS5: контролируемая IP-цель, 3–8 случайных пакетов, проверка relay/source/nonce, TCP lifetime, timeout и отрицательные сценарии.
- Свидетельство хранится в необязательном поле профиля схемы 1; fingerprint и время ограничивают актуальность 15 минутами. Переименование и Enabled не сбрасывают историческое свидетельство; изменение параметров upstream делает его неактуальным.
- Добавлен локальный Python echo-сервер для воспроизводимой лабораторной проверки. Успех relay не включает UDP в генераторе TUN и не заявляет поддержку Discord voice.
- Для служебных DNS-адресов TUN добавлен ограниченный hijack → local/system resolver. Строгая DNS/IPv6-защита пока не предоставляется.
- Открыто: настоящий Windows TUN acceptance TCP/UDP по EXE/name, надёжная атрибуция датаграмм, DNS leakage и IPv6, смена сети, sleep/wake, падение UI/агента/движка, VPN и reboot recovery. После прохождения этих проверок можно отдельно разрешать UDP-ветку генератора для совместимых upstream.

Следующий минимальный шаг после relay-проверки — TUN-прогон с контролируемым upstream и echo endpoint на Windows. Затем проверить Discord voice минимум 10 минут. Тест одного echo endpoint не подтверждает разные размеры пакетов, длительную работу, QUIC, NAT rebinding или все IP-семейства. Явный Direct fallback требует отдельной реализации и отрицательных тестов.

## 3. Дополнительные протоколы — Planned

Добавлять по одному outbound с собственными валидаторами, формой, импортом и TCP/UDP приёмкой: Shadowsocks, VLESS, VMess, Trojan, Hysteria2, TUIC. Поддержку upstream не выводить только из поддержки типа в sing-box.

## 4. PID и потомки — Planned

Провести WFP/ETW feasibility spike: права, точность TCP/UDP атрибуции, повторное использование PID, гонки завершения и различение одинаковых EXE. Принять ADR с вариантом драйвера/службы и моделью подписания. Реализовать правила `(PID,startTime)` и динамических потомков только после успешных проверок. Не преобразовывать эти правила в `process_name`.

## 5. Релиз — Planned

Трей, автозапуск, инсталлятор и удаление, доступность, импорт/экспорт, подпись, лицензии зависимостей, проверка поставки и полный Windows regression. Kill switch и WireGuard требуют отдельных решений. До завершения этих проверок сборка является инженерной первой итерацией.

## Дополнение: стенд TCP TUN

Добавлен воспроизводимый стенд для path/name, двух профилей, отключения и приоритета Block. Подготовка без изменения сети прошла; живой прогон не выполнен из-за пересекающихся VPN-маршрутов и отсутствия административных прав. Этапы остаются Partial. Инструкция: tun-lab.md, результаты: verification-tun-lab.md.
