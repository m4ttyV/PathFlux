# Как пользоваться PathFlux

PathFlux отправляет трафик выбранных программ через ваш прокси. Остальные программы продолжают работать по своим правилам. Вам нужен Windows 10/11 x64, .NET 10 x64 и доступ к прокси-серверу. Адрес, порт, логин и пароль выдаёт владелец прокси. PathFlux не создаёт прокси и не подключает VPN за вас.

Если Windows при открытии программы предлагает установить .NET, согласитесь и установите .NET Runtime 10 для Windows x64 с сайта Microsoft: https://dotnet.microsoft.com/download/dotnet/10.0. После установки снова откройте PathFlux.exe. Версия x86 или ARM64 для этой сборки не подойдёт.

## 1. Первый запуск: установить движок

Распакуйте ВСЮ папку PathFlux в удобное место. Не запускайте EXE прямо из архива и не переносите его отдельно: рядом нужны agent, engine-package и остальные файлы.

Откройте PathFlux.exe. Перейдите в «Настройки» и нажмите «Установить движок PathFlux». Дождитесь сообщения об установке. Программа проверит пакет, установит движок в папку вашего пользователя и сама сохранит путь и SHA-256. Копировать контрольную сумму руками не нужно. Интернет для этой установки не нужен.

Если программа пишет, что пакета нет, получите полную portable-сборку, содержащую папку engine-package. Если ошибка связана с контрольной суммой, получите пакет заново: отключать проверку нельзя.

Движок в комплекте — модифицированная сборка sing-box 1.14.3 для PathFlux. Исходники и лицензия прилагаются. Свою официальную сборку sing-box от 1.12.2 можно указать вручную, но она не поддерживает точное дерево PID.

## 2. Добавить свой прокси

Перейдите в «Профили» → «Новый профиль». Назовите его так, чтобы вам было понятно. Выберите SOCKS5, если хотите использовать голос, видео или игры. HTTP и HTTPS CONNECT работают только с TCP.

В поле «Хост / IP» укажите только адрес сервера, без socks5://, порта и пароля. В соседнее поле внесите порт. Для локального прокси адрес часто 127.0.0.1, но порт нужно взять из его настроек.

Если нужна авторизация, включите замену авторизации и внесите логин и пароль. Нажмите «Сохранить». Пароль хранится отдельно под защитой Windows и после сохранения не показывается.

Для нового SOCKS5-профиля TCP/IPv4 уже включён, UDP настроен на «Автоматически». Существующие профили сохраняют свои настройки. Для обычного начала работы дополнительные поля менять не нужно.

## 3. Выбрать приложение

Сначала запустите приложение, которое хотите направить через прокси. Во вкладке «Процессы» найдите его и выделите строку. Если список устарел, нажмите «Обновить».

Нажмите «Создать по имени». Во вкладке «Правила» выберите созданное правило и проверьте прокси-профиль: автоматически используется первый включённый профиль. Нажмите «Сохранить» после изменений.

Правило по имени действует на все процессы с таким именем файла. «Создать по пути EXE» выбирает конкретное расположение приложения. Правило по имени не включает процессы с другими именами, даже если приложение их запустило.

Для обычных сайтов достаточно TCP. Для голоса, видеосвязи и игр выберите «TCP + UDP» и выполните следующий шаг. Название правила — просто ваша подпись. В поле приложения должно быть настоящее имя EXE или полный путь, а не название с ярлыка.

Если правила пересекаются, раньше применяется правило с меньшим числом приоритета. Остальные приложения по умолчанию идут напрямую. При отказе прокси совпавшее правило Proxy не переключается на Direct.

## 4. Разрешить UDP для голоса и видео

Во вкладке «Настройки» включите «Разрешить UDP через SOCKS5» и нажмите «Сохранить настройки». У нужного правила выберите «TCP + UDP» и сохраните его. Разрешение UDP само по себе не меняет существующие TCP-правила.

SOCKS5-сервер должен поддерживать UDP ASSOCIATE. В автоматическом режиме PathFlux использует выданный сервером релей. Для локального Docker он пытается прочитать опубликованные UDP-порты через Docker Desktop, включая переназначение номера порта. Контейнер и порты должны быть однозначно определены.

Если Docker недоступен или порты определить нельзя, UDP блокируется. В профиле раскройте «Дополнительно: режим UDP и порты Docker», выберите ручной режим Docker и внесите опубликованный диапазон. В этом ручном режиме внешние и внутренние номера портов должны совпадать; публикация должна быть доступна на 127.0.0.1. Диапазон 20000–20030 — только пример, а не стандарт SOCKS5.

Во вкладке «Диагностика» выберите профиль и нажмите «Проверить UDP». Свой echo-сервер не нужен: программа отправит через прокси проверочный DNS-запрос на 1.1.1.1:53 со случайным именем в example.com и проверит ответ. Имена посещённых вами сайтов в этом тесте не используются. Тест не меняет системный DNS и не включает UDP в правилах автоматически. Отказ или тайм-аут означает, что проверка не пройдена; причиной может быть и недоступность проверочного DNS-сервера.

Затем проверьте работу именно своего приложения. Счётчики UDP находятся в «Диагностике». Дополнительный echo-тест предназначен для собственного проверочного UDP-сервера; произвольный сайт вместо него не подойдёт. Сборка не гарантирует совместимость с каждым прокси.

## 5. Запустить и проверить

Нажмите «Проверить». Если найдены ошибки, откройте «Обзор» и исправьте их. Затем нажмите «Запустить» и подтвердите системный запрос Windows: отдельному агенту нужны права для создания TUN.

Откройте НОВОЕ соединение в выбранном приложении. Например, перезапустите браузер и сравните внешний IP с адресом вашего прокси. В голосовом приложении заново подключитесь к каналу. Уже открытое соединение могло сохранить старый маршрут.

Если не работает: проверьте адрес и авторизацию профиля, его выбор в правиле, настоящее имя процесса и тип трафика. Во вкладке «Диагностика» проверьте TCP CONNECT, а для UDP посмотрите счётчики и сообщение последней ошибки. Журнал сессии находится там же; при обращении за помощью скопируйте его сообщение. Секреты и содержимое пакетов в журнал не записываются.

## 6. Остановка, трей и VPN

Крестик скрывает окно в трей, движок продолжает работу. Нажмите значок PathFlux в области уведомлений, чтобы вернуть окно. Чтобы завершить программу, выберите «Выход» в меню значка.

Для изменения профилей, правил или движка сначала нажмите «Остановить». При неподтверждённой остановке приложение остаётся открытым для повторной попытки. Не удаляйте recovery-журнал вручную и не сбрасывайте все маршруты Windows.

Сторонний VPN можно использовать, но он может менять маршруты и DNS. PathFlux проверяет очистку собственных ресурсов отдельно и сохраняет неподтверждённый архив, если общая сеть изменилась. Системного kill switch и полной защиты от утечек системного DNS нет.

Не запускайте несколько копий PathFlux: они используют одни настройки и могут мешать друг другу.

## 7. Дочерние процессы — Experimental

Этот режим пока предназначен для отдельного тестирования и работает только с TCP. Для обычного правила по имени включать его не нужно. UDP в правиле дерева запрещён; TCP-правило дерева не охватывает UDP, который подчиняется остальным правилам и маршруту по умолчанию.

Остановите движок. Установите комплектный движок PathFlux и включите настройку точного дерева PID. Сохраните настройки. Во вкладке «Процессы» найдите ГЛАВНЫЙ процесс приложения: ориентируйтесь на PID родителя. Выберите одну строку и нажмите «Дерево выбранного PID». Выберите профиль и сохраните правило TCP.

Пример: главный процесс с PID 100 запускает процессы 101 и 102. Чтобы охватить обе ветви, выбирайте 100. Дерево для 101 не охватит соседний процесс 102. Новые дети и внуки выбранного корня подхватываются без ручного добавления.

Правило относится к конкретному запуску. После перезапуска приложения отключите старое правило и создайте новое для его нового PID. Для чистой проверки дерева временно отключите перекрывающие правила этого же приложения по имени или пути. Неподтверждённая принадлежность блокируется; все возможные гонки и длительная нагрузка ещё не приняты.
