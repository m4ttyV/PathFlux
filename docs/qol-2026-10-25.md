# Упрощение настройки PathFlux — 25.10.2026

## Изменения для пользователя

- Вверху окна — «Как пользоваться». Встроена [пошаговая инструкция](user-guide.md), доступная без интернета.
- В настройках — «Установить движок PathFlux». Проверенный комплектный sing-box устанавливается в `%LOCALAPPDATA%/PathFlux/engines/<sha256>/`, путь и SHA-256 заполняются и сохраняются вместе. UAC и интернет для установки не нужны. При ошибке установки или сохранения прежний настроенный движок сохраняется.
- Portable-пакет содержит engine-package с бинарником, изменёнными исходниками ZIP, лицензией и manifest. Это модифицированный sing-box 1.14.3, а не официальный бинарник. Пользователь может указать официальный выпуск вручную, но дерево PID ему недоступно.
- У новых SOCKS5-профилей UI включён TCP/IPv4 и выбран режим UDP «Автоматически». Значения существующих профилей не меняются. Разрешение UDP в настройках по-прежнему нужно включить отдельно, затем выбрать UDP или TCP + UDP в нужном правиле.
- При создании правила имя и приложение пустые, с понятными подсказками. Тип выбора приложения и действие переведены на русский. В списке процессов показан PID родителя.
- Пометка Experimental в текущем интерфейсе оставлена для дерева PID. Это изменение представления, а не новая приёмка неподтверждённых сетевых возможностей. Исторические отчёты и ограничения сохраняются.

## Автоматический UDP

Для обычного SOCKS5 используется релей из ответа UDP ASSOCIATE. Если локальный прокси возвращает частный IPv4 контейнера, resolver читает только `GET /containers/json?all=false` локального Docker Engine через Windows named pipe docker_engine или dockerDesktopLinuxEngine. Удалённый Docker и shell-команды не используются. Требуется доступ пользователя/агента к Docker Desktop.

Совпасть должны TCP-публикация прокси, IP контейнера из ответа и его UDP-порт. Только однозначное опубликованное IPv4-сопоставление разрешает замену на loopback. Поддерживается и другой номер порта на хосте. IP контейнера, сеть и диапазон портов не зафиксированы в коде. Метаданные Docker не попадают в журнал; размер ответа ограничен, попытки имеют тайм-аут.

При отсутствии доступа, неоднозначных или повреждённых метаданных запрос отклоняется. Нет сканирования loopback, угадывания портов или Direct fallback. Дополнительные настройки профиля позволяют явно выбрать Standard или ручной Docker NAT с диапазоном. В ручном режиме host/container номера портов должны совпадать. Не все варианты NAT могут быть определены автоматически.

Кнопка «Проверить UDP» выполняет одну DNS-транзакцию через SOCKS5 к 1.1.1.1:53 со случайным проверочным именем в example.com. Проверяются управляющая TCP-ассоциация, SOCKS-адрес/порт отправителя, FRAG=0, DNS ID и вопрос. Простой echo, некорректный ответ или успешный ASSOCIATE не засчитываются как передача. DNS-ответ NXDOMAIN также доказывает передачу UDP. Системный DNS и правила не меняются; автоматического разрешения UDP нет. Недоступность DNS-сервера может привести к отрицательному результату даже при поддержке другого UDP-трафика.

`ExperimentalSocksUdp` в JSON сохранён как прежнее имя поля ради совместимости. Внутренние статусы возможностей не повышались автоматически. Правила дерева UDP по-прежнему отклоняются до TUN.
