# Проверка запуска сетевого агента

Проверка конфигурации (`sing-box check`) не запускает агент, UAC или TUN. Поэтому она может пройти, а запуск затем завершиться ошибкой.

В исправлении 24.10.2026 канал UI–агент использует явный защищённый DACL по `WindowsIdentity.User`, а не `PipeOptions.CurrentUserOnly`. В .NET 10 этот флаг сравнивает Owner токена; Owner может различаться до и после повышения прав одного пользователя. Причина подтверждается [исходниками .NET 10](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.IO.Pipes/src/System/IO/Pipes/NamedPipeClientStream.Windows.cs) и [описанием ошибки runtime](https://github.com/dotnet/runtime/issues/123903). Это возможная причина отказа после UAC; без точного исходного сообщения нельзя установить, что пользователь встретил именно её.

Новый канал даёт доступ только SID пользователя, запрещает сетевые входы, не разрешает агенту делегировать UI свои права через impersonation и сохраняет проверку PID с обеих сторон. Агент проверяет PID и время создания родителя, а также владельца канала. Вход через UAC должен использовать ту же учётную запись Windows; ввод данных другого администратора не поддерживается.

Интерфейс теперь показывает безопасное сообщение движка в уведомлении и журнале, вместо одного типа `InvalidOperationException`. Произвольные исключения и необработанные сообщения upstream по-прежнему скрыты. При раннем выходе агента объясняются отсутствие прав, занятая сессия, несовпадение процессов, отказ доступа к каналу и таймаут. Нужно обновлять всю portable-папку, включая `agent`, а не только EXE интерфейса.

## Проверка связи без движка и TUN

В portable-папке выполнить:

```powershell
$agent = (Resolve-Path '.\agent\PathFlux.Agent.exe').Path
.\network-lab\PathFlux.NetworkLab.exe agent-check $agent
```

Команда вызывает UAC для настоящего агента, проверяет канал и выполняет только `status` и `stop`. Она не передаёт конфигурацию или пароли, не запускает sing-box, не создаёт TUN и не меняет сеть. Ожидаемый результат: `AgentConnectionPassed_NoEngineOrTunStarted` и код 0. Это проверка доставки portable-агента и IPC; для сетевого запуска требуется отдельная проверка TUN.

Автотесты проверяют реальный канал с дочерним процессом, ограничение ACL SID пользователя, запрет Network SID, отказ при неверном PID, фиксированные сообщения кодов выхода и показ безопасной ошибки в UI без раскрытия неизвестных исключений. Обычные автотесты не вызывают UAC.

## «Остановка не подтверждена» после завершения процессов

На рабочей машине обнаружен конкретный случай: агент и sing-box уже отсутствуют, `Get-NetAdapter` не возвращает PathFlux-TUN, но .NET GetAllNetworkInterfaces сохраняет запись с именем PathFlux-TUN, статусом Down, без IPv4/IPv6, адресов и DNS. Прежняя проверка только по имени блокировала и остановку, и следующий запуск.

Теперь игнорируется только полностью отсоединённая запись: Down либо NotPresent, оба IP-протокола отсутствуют, число адресов и DNS равно нулю. Один лишь Down не считается очисткой. Если остался IP-протокол, адрес, DNS или активное состояние, подтверждение остановки запрещено. Объект присутствия агента открывается только с правом Synchronize; доступ на изменение из обычного UI не требуется.

При разрыве IPC UI закрывает канал и до пяти секунд ждёт завершения агента и очистки IP-интерфейса. Первоначальная ошибка запуска сохраняется, если остановку всё же нельзя подтвердить. Готовность TUN при запуске проверяется до 12 секунд, вместо фиксированной задержки 1,8 секунды; имя фантомного адаптера не доказывает готовность.

Проверка без изменений сети на текущей машине:

```powershell
.\network-lab\PathFlux.NetworkLab.exe recovery-check
```

Команда намеренно отклоняет пустые настройки до запуска агента, затем проверяет переход из Failed в Stopped. На обнаруженном фантомном адаптере опубликованная сборка вернула `RecoveryCheckPassed_NoEngineOrTunStarted`. После исправления полный набор: **309 passed, 0 failed, 0 skipped**, сборки без предупреждений. Добавлено 14 проверок фантомного состояния, неполной очистки и готовности. Команда не удаляет адаптеры, маршруты или recovery-журнал и не подтверждает восстановление произвольных сторонних изменений сети.

## Результат проверки 24.10.2026

Release-сборка: 0 предупреждений, 0 ошибок. Полный набор с официальным sing-box 1.14.3: **295 passed, 0 failed, 0 skipped** (App 24, Engine 56, Infrastructure 92, Policy 123).

Опубликованный `network-lab/PathFlux.NetworkLab.exe agent-check` успешно запустил настоящий опубликованный агент с повышенными правами, подтвердил PID и канал, выполнил status/stop и получил код завершения 0: `AgentConnectionPassed_NoEngineOrTunStarted`. Проверка не отправляла команду start и не изменяла сеть. Это подтверждает исправленный путь запуска и IPC, но не успешное создание TUN в конкретной пользовательской конфигурации. Исходное сообщение ошибки пользователя было известно только как `InvalidOperationException`, поэтому его точная причина остаётся неподтверждённой.
