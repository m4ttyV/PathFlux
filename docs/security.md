# Привилегии и секреты

UI выполняется с обычными правами. Кнопка Start запускает отдельный PathFlux.Agent.exe через UAC. Агент принимает только типизированные start/status/stop и пересобирает JSON из доменной конфигурации. Произвольные команды, backend JSON, netsh и shell не принимаются. ProcessStartInfo.ArgumentList отделяет аргументы; shell-concatenation отсутствует.

Локальный named pipe имеет случайное имя и защищённый DACL только для SID пользователя с запретом сетевых входов. Для совместимости с UAC флаг CurrentUserOnly заменён явным User SID; см. agent-startup.md. UI проверяет PID подключившегося агента; агент проверяет PID сервера и `(PID, StartTime)` родительского UI. Оба направления имеют ограничение 1 MiB и timeout. Агент прекращает работу при закрытии pipe, потере родителя или 30 сек без запроса. UAC с учётными данными другого пользователя не поддержан: другой SID не получит доступ к pipe/DPAPI. Это не Windows service с долговременным endpoint.

Агент независимо сверяет EXE с сохранённым SHA-256, проверяет версию ≥ 1.12.2 и Windows x64, удерживает файл открытым без разрешения записи/удаления и вызывает check перед run. Хеш подтверждает соответствие выбранному файлу, а не подлинность издателя: использовать официальный скрипт, который проверяет SHA-256 архива по метаданным релиза GitHub. Пользовательский SHA-256 не является встроенным списком доверенных подписей. Скачивание только явным скриптом, никаких автообновлений. Каталог опубликованного приложения и agent должен быть доверенным: подпись собственного агента/installer — будущий релизный этап.

Job Object с KILL_ON_JOB_CLOSE привязывается к sing-box **до** передачи JSON и EOF в stdin: до этой точки движок не может прочитать конфигурацию и изменить сеть. При аварии агента Windows завершает дочерний движок. Движок назначает адреса, маршруты и DNS своему новому TUN; исходные адаптеры и firewall не перенастраиваются. Для остановки используется завершение процесса и закрытие handle TUN; graceful Windows control-plane sing-box в этой итерации не реализован. После остановки агент проверяет подключённое состояние своего IP-интерфейса; полностью отсоединённая запись Down без IP-протоколов, адресов и DNS не мешает остановке. Если осталась конфигурация IP-интерфейса, возвращает Failed и сохраняет recovery journal. Повторный Stop не скрывает непроверенное состояние; UI дополнительно проверяет отсутствие TUN и живого агента. Не гарантируются все сценарии reboot/sleep/VPN и отсутствие остатков маршрутов — ручной acceptance обязателен.

DPAPI использует CRYPTPROTECT_UI_FORBIDDEN, CurrentUser, без LocalMachine. Обычный JSON содержит только случайный credentialsRef. Секреты передаются pipe → оперативная память → stdin; backend JSON на диск не пишется. stdout/stderr движка полностью поглощаются и не отображаются: upstream может вернуть чувствительные данные. UI пишет ограниченный журнал безопасных событий; полные исключения не журналируются. Часть управляемых строк может оставаться в памяти до GC; memory dump защищается ОС, отдельной гарантии против дампа процесса нет.

Atomic JSON + backup сохраняют предыдущее валидное состояние, а неизвестная будущая схема блокирует запись. Секреты, на которые ссылается резервная или повреждённая копия, сохраняются для восстановления. Нельзя удалять credentials вручную, пока нужен backup. Консервативное сохранение может оставлять неиспользуемые DPAPI-файлы; отдельная сборка мусора хранилища пока не реализована. Полный экспорт секретов, облако, telemetry и subscriptions отсутствуют.

Loopback и точные пути UI/agent/engine исключаются перед пользовательскими правилами. LAN bypass только явный. DNS — System/direct, строгий режим без утечек не предоставляется. Proxy failure не имеет скрытого Direct fallback; новое соединение падает в работающем движке. При его аварии Direct ОС может возобновиться — это **не** системный kill switch. Отключение Defender, firewall или проверки TLS не используется.

UDP echo создаёт собственную ограниченную ассоциацию к выбранному SOCKS5 и отправляет только случайные диагностические данные к явно заданной IP-цели. TCP-контроль и внешний адрес relay проверяются; прямого обхода цели нет. История проверки хранит адрес цели, время и счётчики, но не payload/nonce и не учётные данные. Она считается непроверенным локальным метаданным и никогда не включает привилегированную UDP-маршрутизацию TUN. Срок 15 минут — актуальность истории короткого теста, не гарантия доступности upstream в будущем.

После сетевого аудита агент атомарно сохраняет baseline таблицы маршрутов, DNS и адресов адаптеров до передачи конфигурации движку. После Stop отдельно проверяются удаление собственных ресурсов и полное совпадение сети. Остатки TUN/маршрутов/адресов/DNS PathFlux сохраняют журнал и Failed. Если собственные ресурсы удалены, а сторонний VPN или DHCP изменил сеть, остановка завершается с предупреждением; после выхода агента UI сохраняет оригинал в `.unconfirmed-network-change-...`. Это не подтверждает полное восстановление и не перенастраивает стороннюю сеть. Недоступный или повреждённый журнал по-прежнему блокирует запуск. Строгая команда recover-journal архивирует как verified только при полном совпадении сети и отсутствии агента; recover-owned допускает неподтверждённый архив после независимой проверки собственных ресурсов. [Переходы VPN](vpn-transition-recovery.md). Журнал содержит локальную топологию и не предназначен для автоматической публикации. В NetworkLab ограниченная диагностика разрешена только для генерируемых конфигураций без credentials; production stderr по-прежнему не сохраняется.

В схеме 2 прозрачный UDP доступен только после ручного opt-in; миграция схемы 1 оставляет его выключенным. Посредниками владеет агент: UI не открывает транспортные слушатели, предварительная проверка использует только инертный descriptor для `sing-box check`. Каждый действующий посредник слушает IPv4 loopback, требует случайные credentials, отклоняет ненулевой FRAG и некорректные пакеты. Docker NAT требует явного режима и диапазона публикации, использует loopback TCP peer и динамический BND.PORT. Отказ не переключает живой TUN на Direct. Локальная запись JSONL включается вручную, содержит агрегаты и PID движка без payload и секретов; облачная отправка отсутствует. Ограничения и результаты: [этап 3](udp-production-stage3.md).
