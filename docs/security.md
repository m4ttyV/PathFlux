# Привилегии и секреты

UI выполняется с обычными правами. Кнопка Start запускает отдельный PathFlux.Agent.exe через UAC. Агент принимает только типизированные start/status/stop и пересобирает JSON из доменной конфигурации. Произвольные команды, backend JSON, netsh и shell не принимаются. ProcessStartInfo.ArgumentList отделяет аргументы; shell-concatenation отсутствует.

Локальный named pipe имеет случайное имя и CurrentUserOnly. UI проверяет PID подключившегося агента; агент проверяет PID сервера и `(PID, StartTime)` родительского UI. Оба направления имеют ограничение 1 MiB и timeout. Агент прекращает работу при закрытии pipe, потере родителя или 30 сек без запроса. UAC с учётными данными другого пользователя не поддержан: другой SID не получит доступ к pipe/DPAPI. Это не Windows service с долговременным endpoint.

Агент независимо проверяет SHA-256 закреплённого официального EXE, удерживает файл открытым без разрешения записи/удаления и вызывает check перед run. Неверифицированная версия не запускается даже с произвольным hash в настройках. Скачивание только явным скриптом, никаких автообновлений. Каталог опубликованного приложения и agent должен быть доверенным: подпись собственного агента/installer — будущий релизный этап.

Job Object с KILL_ON_JOB_CLOSE привязывается к sing-box **до** передачи JSON и EOF в stdin: до этой точки движок не может прочитать конфигурацию и изменить сеть. При аварии агента Windows завершает дочерний движок. Движок назначает адреса, маршруты и DNS своему новому TUN; исходные адаптеры и firewall не перенастраиваются. Для остановки используется завершение процесса и закрытие handle TUN; graceful Windows control-plane sing-box в этой итерации не реализован. После остановки агент проверяет наличие своего интерфейса; если он остался, возвращает Failed и сохраняет recovery journal. Повторный Stop не скрывает непроверенное состояние; UI дополнительно проверяет отсутствие TUN и живого агента. Не гарантируются все сценарии reboot/sleep/VPN и отсутствие остатков маршрутов — ручной acceptance обязателен.

DPAPI использует CRYPTPROTECT_UI_FORBIDDEN, CurrentUser, без LocalMachine. Обычный JSON содержит только случайный credentialsRef. Секреты передаются pipe → оперативная память → stdin; backend JSON на диск не пишется. stdout/stderr движка полностью поглощаются и не отображаются: upstream может вернуть чувствительные данные. UI пишет ограниченный журнал безопасных событий; полные исключения не журналируются. Часть управляемых строк может оставаться в памяти до GC; memory dump защищается ОС, отдельной гарантии против дампа процесса нет.

Atomic JSON + backup сохраняют предыдущее валидное состояние, а неизвестная будущая схема блокирует запись. Секреты, на которые ссылается резервная или повреждённая копия, сохраняются для восстановления. Нельзя удалять credentials вручную, пока нужен backup. Консервативное сохранение может оставлять неиспользуемые DPAPI-файлы; отдельная сборка мусора хранилища пока не реализована. Полный экспорт секретов, облако, telemetry и subscriptions отсутствуют.

Loopback и точные пути UI/agent/engine исключаются перед пользовательскими правилами. LAN bypass только явный. DNS — System/direct, строгий режим без утечек не предоставляется. Proxy failure не имеет скрытого Direct fallback; новое соединение падает в работающем движке. При его аварии Direct ОС может возобновиться — это **не** системный kill switch. Отключение Defender, firewall или проверки TLS не используется.
