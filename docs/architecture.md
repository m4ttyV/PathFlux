# Архитектура PathFlux

Существующий Avalonia-проект `PathFlux/` сохраняется как непривилегированный UI. .NET 10.0.401, Avalonia 11.3.11, CommunityToolkit.Mvvm 8.2.1. Отдельные проекты Domain (модели), Application (контракты и компилятор правил), Infrastructure (атомарный JSON, DPAPI, процессы, диагностика), Engine (sing-box JSON и контроль агента), Agent (привилегированный надзор). Тесты не требуют TUN.

Порядок: (0) каркас и проверка источников; (1) рабочие формы и persistence, детерминированная компиляция, локальные TCP-тесты, lifecycle; затем (2) реальные UDP/DNS/Windows acceptance; (3) дополнительные outbounds; (4) WFP feasibility для PID; (5) релиз. Статус сетевой поддержки определяется доказательствами, а не наличием поля JSON.

Выбран sing-box через отдельный процесс, без WinDivert. Конфигурация домена независима от его JSON. PID `(pid,startTime)` присутствует в модели, но не преобразуется в EXE-правило. IncludeChildren и системный kill switch недоступны. По умолчанию Direct; сначала исключения собственных процессов и loopback, затем приоритет и UUID. Недоступный UDP блокируется в совпавшем правиле; явный fallback разрешается только для документированного случая, неподдерживаемая семантика отклоняется.

TUN затрагивает системный маршрут даже для Direct. UI не повышает права; запускает ограниченный агент с UAC. Агент проверяет конфигурацию и доверенный бинарник, владеет движком, останавливает его при потере UI/IPC. Секреты передаются локальным каналом и в stdin движка, не обычным JSON-файлом. Восстановление и ограничения описаны в network-design.md и security.md.

Полный сетевой acceptance Windows требует отдельного разрешённого запуска TUN и подходящего upstream. Сборка/локальные тесты не доказывают прозрачную маршрутизацию.

В [этапе 3](udp-production-stage3.md) агент также владеет строгими SOCKS5 UDP-посредниками: отдельный outbound для UDP на профиль, явный Docker NAT с динамическим портом, закрытие при Stop/падении и агрегированная диагностика через status IPC. UI включает функцию только вручную, схема 2 мигрирует старые настройки с выключенным opt-in. Длительная работа Discord, защищённый per-app DNS и системный kill switch не подтверждены либо не поддерживаются; актуальные статусы приведены в [матрице возможностей](limitations.md).
