# DNS и OpenVPN WFP: этап 3

Статус защищённого per-app DNS: **Not Verified**, реализация выключена. Доступен только существующий System DNS. Изменений глобальных DNS Windows, NRPT и сторонних WFP-фильтров не выполнялось.

Позднее добавлен отдельный экспериментальный DoH JSON resolver только для преобразования выбранного IPv6 TLS-соединения в IPv4 через SOCKS5: [совместимость Discord](discord-connectivity-2026-10-24.md). Он не перехватывает первоначальный DNS приложения, не заменяет System DNS и не подтверждает общую защиту от DNS leaks.

Снимок исходного аудита выявил OpenVPN BLOCK для remote port 53 на ALE_AUTH_CONNECT IPv4/IPv6 с разрешением VPN-интерфейса. Тест DNS к 1.1.1.1 через TUN не дошёл до UDP-посредника. Успех DNS через SOCKS5 relay без TUN не отменяет эту блокировку перед TUN. Приёмка обычного UDP использует STUN/3478 и не объявляет защищённый DNS работающим.

## Рассмотренные варианты

| Вариант | Возможность | Нерешённое |
|---|---|---|
| Управляемый DNS sing-box + hijack виртуальных TUN DNS | Разрешение внутри движка, без собственной глобальной Windows DNS-службы | Hijack действует только на дошедший до TUN пакет; фильтр WFP раньше TUN он не обходит |
| DNS-over-HTTPS через TCP outbound выбранного SOCKS5 | Зашифрованный DNS upstream по detour; bootstrap IP и TLS SNI с обязательной проверкой | Нельзя произвольно приписать DNS Windows выбранному приложению: запрос часто отправляет общая служба DNS Client. Нужны доказательство атрибуции, bootstrap и отказные тесты |
| DNS-over-TLS через TCP outbound | Аналогичное разделение resolver/transport | Порт 853 может отдельно фильтроваться; нужны независимые проверки и безопасный bootstrap |
| Раздельный служебный DNS и DNS выбранных приложений | Отдельные resolver/outbound для поиска proxy host и данных приложения | Не разрешать циклическую зависимость DNS → proxy host → DNS; не перенаправлять запросы всех приложений без явного выбора пользователя |

sing-box поддерживает HTTPS DNS server и dial fields, включая `detour`: [HTTPS DNS](https://sing-box.sagernet.org/configuration/dns/server/https/), [Dial Fields](https://sing-box.sagernet.org/configuration/shared/dial/). Эти документы подтверждают механизм, а не его работу в нашем Windows/WFP-окружении. Из наличия полей не следует защита от утечек.

Предпочтительное отдельное продолжение — управляемый DoH по TCP detour с независимым служебным bootstrap, строгой TLS-проверкой и доказанной областью запросов. Перед включением нужны тесты packet capture/наблюдаемого resolver, несовпавших приложений, отказа DoH/прокси, кеша, IPv6, Windows DNS Client и сочетания с текущим OpenVPN. Не использовать скрытый System/Direct fallback при отказе защищённого resolver. До такой приёмки генератор не добавляет обещающий защиту DNS-режим, а валидатор отклоняет неподдерживаемый DnsMode.
