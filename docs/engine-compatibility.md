# Совместимость с sing-box от 1.12.2

Минимальная версия — **1.12.2**. Приложение больше не содержит списка допустимых SHA-256 одной версии. Новый EXE требует собственного хеша в настройках. Поддерживаемая платформа остаётся Windows x64.

Перед проверкой конфигурации UI сверяет SHA-256, затем вызывает `sing-box version`. Агент независимо повторяет эти шаги перед `check` и `run`. Файл удерживается открытым без разрешения записи/удаления; несовпадение хеша или версия ниже минимальной отклоняются. Ответ `version` ограничен 4096 символами и 10 секундами, stderr не сохраняется. Непонятный формат или другая платформа также отклоняются.

Сравниваются числовые major/minor/patch, а не строки: 1.12.12 новее 1.12.2. Предварительная 1.12.2-rc.1 ниже минимальной стабильной и отклоняется. Более новые prerelease допускаются через ручной выбор EXE и хеша, но отдельно не подтверждены сетевой приёмкой. Скрипт загрузки принимает только стабильные версии.

## Загрузка и настройка

```powershell
# По умолчанию выбран стабильный выпуск 1.14.3.
$engine = .\scripts\get-engine.ps1
# Либо конкретная версия:
$engine = .\scripts\get-engine.ps1 -Version 1.12.2 -Destination '.local\engine-1.12.2'
$engine
```

В настройках указать `EnginePath` и `EngineSha256` из результата скрипта. При обновлении заменить оба значения. Старые настройки с EXE и хешем 1.12.12 продолжают работать без миграции JSON.

Скрипт запрашивает официальный GitHub release по точному тегу и SHA-256 Windows amd64 архива из asset metadata. Если digest отсутствует, загрузка отклоняется. После сверки архива он извлекает EXE и возвращает его SHA-256, не запуская скачанный файл. Хеш из настроек подтверждает соответствие выбранному файлу; сам по себе пользовательский хеш не удостоверяет издателя.

## Конфигурация и будущие версии

Используются DNS-формат и route actions, доступные с 1.12. Для версий от 1.15 генератор не задаёт устаревающее поле TUN `stack`, используя реализацию по умолчанию. Это соответствует [официальной миграции TUN](https://sing-box.sagernet.org/migration/#migrate-tun-stack). Стенд учитывает то же изменение.

Верхняя граница версии не задана. Каждая установленная версия должна принять конкретную конфигурацию через `sing-box check`; отказ выводится как ошибка совместимости до запуска TUN. Это не обещание совместимости с ещё неизвестными изменениями будущих релизов. Успех `check` и тестов loopback не подтверждает маршрутизацию настоящего Windows TUN, DNS leakage или UDP через правила приложения.

## Тестирование

```powershell
$env:PATHFLUX_TEST_ENGINE = $engine.EnginePath
$env:PATHFLUX_TEST_ENGINE_SHA256 = $engine.EngineSha256
dotnet test PathFlux.slnx -c Release
.\scripts\run-tun-lab.ps1 -EnginePath $engine.EnginePath -EngineSha256 $engine.EngineSha256
```

Без переменной пути внешние тесты пропускаются. Без переменной SHA для старых команд тестов используется только исторический хеш фикстуры 1.12.12; рабочее приложение такого исключения не имеет. Windows CI настроен на 1.12.2, 1.12.12, 1.13.21, 1.14.3. Для каждого выпуска загружается отдельный проверенный архив; реальный TUN в CI не запускается.
