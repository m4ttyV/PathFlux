# Реальные возможности текущей версии

Статус на 24.10.2026, после живого TCP TUN-аудита (network-audit-2026-10-24.md). `Implemented` означает реализованную и локально тестируемую часть; это не подтверждение прозрачной маршрутизации Windows. `Partial / NotVerified` означает наличие кода с обязательной отдельной сетевой приёмкой. Результаты первой итерации сохраняются в отчёте проверки; текущие возможности перечислены ниже.

| Возможность | Код / unit-проверки | Сетевая приёмка Windows |
|---|---|---|
| Список процессов, PID и доступный путь | Implemented; отказ доступа к защищённому процессу обработан | Не доказывает атрибуцию сетевых потоков |
| Постоянное правило по имени EXE | Implemented: модель, валидация, компиляция `process_name` | Partial: подтверждено на Windows 11, включая UAC-агент и Docker SOCKS5 |
| Постоянное правило по абсолютному пути EXE | Implemented: модель, валидация, компиляция `process_path` | Partial: две копии одного EXE в разных каталогах проверены через TUN |
| Точный экземпляр `(PID, startTime)` | Unsupported: интерфейс предусмотрен, компилятор отклоняет | Требуется исследование WFP/атрибуции |
| IncludeChildren / UntilProcessExit | Unsupported: активные правила отклоняются | Требуется отдельная реализация с учётом повторного PID |
| Приоритет, включение и выключение, Direct / Block / Proxy | Implemented: детерминированный компилятор и генератор | Partial: проверено в NetworkLab; полный production Block/Direct отдельно от narrow-стенда не принят |
| SOCKS5 TCP | Implemented: outbound, диагностика CONNECT, защищённые credentials | Partial: path/name и отказ upstream через production TUN подтверждены на Windows 11/Docker |
| HTTP CONNECT TCP | Implemented: outbound и диагностика | Прозрачный selective TCP не подтверждён |
| HTTPS CONNECT TCP | Implemented: outbound TLS, проверка сертификата включена | Внешний сервер и его цепочка сертификатов требуют проверки |
| UDP через SOCKS5 / HTTP / HTTPS | Unsupported в маршрутизации: совпавший Proxy UDP получает `reject` | Успех UDP ASSOCIATE сам по себе не подтверждает UDP-передачу |
| UDP ASSOCIATE диагностика SOCKS5 | Implemented: проверка согласования ассоциации и причин отказа | Успешный ASSOCIATE не подтверждает передачу датаграмм |
| UDP echo через SOCKS5 relay | Implemented: 3–8 случайных пакетов, точные ответы, защита от дубликатов и чужого endpoint, сохранение результата | Подтверждает только выбранный echo endpoint через relay; TUN и Discord voice не проверены |
| Актуальность результата UDP echo | Implemented: fingerprint профиля, окно 15 минут, проверка метаданных | Историческое свидетельство, не гарантия доступности сервера сейчас и не разрешение UDP TUN |
| Direct fallback при сбое Proxy | Unsupported: компилятор явно отклоняет | Не заменяется скрытым Direct |
| Kill switch при аварии движка / UI / ОС | Unsupported | Block защищает только совпавший поток внутри работающего движка |
| DNS | Partial: служебный hijack виртуальных DNS TUN → local/system resolver, исключающий TUN | Нет гарантии DNS через выбранный upstream и отсутствия DNS leaks |
| IPv4 / IPv6 | Partial: адреса TUN обоих семейств формируются | IPv4 TCP проверен; IPv6-трафик и строгий режим без утечек не приняты |
| Восстановление маршрутов | Partial: baseline маршрутов/DNS/адресов, проверка после остановки, журнал неопределённого состояния | Штатная остановка, авария движка и закрытие job проверены; сон, смена сети, гибель UI/агента и reboot требуют проверки |
| Shadowsocks, VLESS, VMess, Trojan, Hysteria2, TUIC, WireGuard | Planned | В MVP отсутствуют |
| Установщик, автозапуск, трей, импорт URI | Planned | В MVP отсутствуют |

TUN использует системные маршруты. Даже Direct-потоки могут проходить через движок. Это отличается от перехвата только выбранного процесса и может влиять на VPN, локальную сеть и защищённые приложения. Runtime-статус `Running` означает работающий дочерний процесс движка, а не доказанный upstream-маршрут.

PathFlux пока нельзя применять как подтверждённую защиту от утечек: `strict_route` выключен, DNS системный, точная атрибуция и восстановление после всех сбоев не доказаны. Встроенные исключения полных путей собственных процессов и loopback имеют приоритет над пользовательскими правилами. Дополнительный LAN bypass включается явно; это исключение может перекрыть пользовательский Block / Proxy для непубличных адресов.

Отключённые правила не попадают в таблицу движка. Их неподдерживаемые селекторы и ссылки могут храниться как черновики; UUID и имя проверяются всегда. Включение такого правила повторно запускает полную проверку. Профили проверяются и в отключённом состоянии, а активное правило не может ссылаться на отключённый профиль. Некорректная политика не компилируется частично.

Результат UDP echo относится к конкретным настройкам профиля, IP/порту цели и времени. Имя профиля и Enabled не меняют идентичность upstream; смена endpoint, протокола, credentialsRef или TLS server name требует нового теста. Истёкшее, будущее, несовместимое или некорректное свидетельство не считается актуальным. Даже актуальный `Verified` не изменяет правило: совпавший Proxy UDP продолжает отклоняться. Произвольные DNS-имена echo-цели, scoped/link-local IPv6, multicast, broadcast и неопределённые адреса не поддерживаются. [Как выполнить проверку](udp-diagnostics.md).

Локальные unit-тесты компилятора проверяют UUID, приоритеты, disabled-семантику, отрицательные селекторы и профили, ограничения PID/children/fallback и предупреждение UDP. Тесты свидетельств проверяют fingerprint, старение и некорректные метаданные. Локальные сетевые тесты диагностики работают через подконтрольные SOCKS5/echo endpoints. Эти проверки не запускают TUN и не считаются интеграционной приёмкой selective routing из ТЗ.

Экспериментальный UDP через TUN доступен только NetworkLab через строгий посредник PathFlux. Он отклоняет все SOCKS-фрагменты вместо небезопасной доставки из штатного parser sing-box 1.14.3. Правила path/name, отказные сценарии, переподключение и реальный STUN через Docker/Dante/OpenVPN проверены; для Docker адрес релея явно преобразуется в loopback, а динамический порт проверяется по диапазону публикации. Прямой DNS/53 под TUN в текущей системе блокируется WFP-фильтрами OpenVPN. Production UDP остаётся Unsupported/Reject; длительные Discord voice/video, IPv6 и lifetime в production-агенте не приняты. [Подробный отчёт](udp-transport-audit-2026-10-24.md).
