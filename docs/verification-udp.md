# Вторая итерация: проверка UDP relay — 24.10.2026

Добавлена работающая проверка UDP-пакетов через SOCKS5 relay и её интерфейс. Она не требует TUN, прав администратора или изменений системной сети. Этап 2 остаётся Partial: прозрачная маршрутизация UDP по EXE и Discord voice ещё не подтверждены.

## Реализовано

- Отдельный контракт IUdpRelayDiagnostics и SOCKS5 UDP echo-проверка по RFC 1928. UDP-сокет привязывается до ASSOCIATE, TCP-контроль остаётся открытым. Проверяются 3–8 разных случайных payload по 64 байта, адрес и порт отправителя/цели, заголовок SOCKS и отсутствие фрагментации. Неверные, повторные и чужие ответы не засчитываются.
- Результат различает Verified, Unsupported и Failed; содержит счётчики и средний RTT. ASSOCIATE без echo по-прежнему не подтверждает передачу пакетов. При отказе нет прямой отправки диагностических данных в обход прокси.
- Необязательная история проверки в profiles[].udpVerification, совместимая со схемой 1. Fingerprint связывает её с настройками upstream; срок актуальности — 15 минут. Изменение адреса, протокола или авторизации требует повторной проверки. Payload и nonce не сохраняются.
- Отдельная кнопка UDP echo в UI, явно заданный пользователем IP/порт, сохранение результата и отображение актуальности. Изменение профилей заблокировано при работающем движке. Неправдоподобные даты не вызывают переполнение при показе срока действия.
- Контролируемый echo-сервер scripts/udp-echo-server.py; входит в portable-папку вместе с get-engine.ps1. Python нужен только для этого вспомогательного сервера.
- Лабораторные тесты официального sing-box с настоящими UDP-пакетами через отдельный upstream и echo-сокет. CI теперь получает закреплённый официальный бинарник с проверкой hash для этих тестов; удалённый workflow в этой сессии не запускался.

Запуск тестов:

```powershell
dotnet restore PathFlux.slnx --locked-mode
$installed = ./scripts/get-engine.ps1
$env:PATHFLUX_TEST_ENGINE = $installed.EnginePath
dotnet test PathFlux.slnx -c Release --no-restore -m:1 -nr:false -p:UseSharedCompilation=false --logger trx --results-directory TestResults
./scripts/publish.ps1
```

В финальном локальном прогоне PATHFLUX_TEST_ENGINE указывал на ранее сверенный официальный v1.12.12 в .local/engine/unpacked/. Без переменной среды три внешних engine-теста пропускаются, а не выдаются за успешные. Финальные тесты выполнены вне sandbox, поскольку её ограничения мешают VSTest/процессам MSBuild. Локальные TRX сохранены в игнорируемом TestResults/.

## Что доказано лабораторией

Успешная цепочка: клиент диагностики → официальный sing-box → SOCKS5 с авторизацией → независимый UDP echo. Отдельные счётчики подтверждают три разных пакета на relay и echo-сервере. При REP=7 от upstream напрямую доступный echo-сервер получает ноль пакетов.

Для этого теста **только внутри тестового проекта** TUN заменён loopback SOCKS-входом, правила процессов заменены выходом к лабораторному upstream, а ограничение network=tcp снято. Рабочая конфигурация приложения не менялась. Генератор продолжает отклонять Proxy UDP даже при свежем результате Verified; это проверяет отдельный regression-тест.

Проверки также покрывают аутентификацию, обрывы TCP-контроля, потерю ответов, поддельный payload/адрес/порт/внешний источник, некорректные пакеты, фрагментацию, wildcard/domain relay, IPv4/IPv6 в контролируемой лаборатории, отмену, таймаут, старение результата, совместимость JSON и откат при ошибке сохранения.
